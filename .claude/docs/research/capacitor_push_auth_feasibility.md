# Capacitor プッシュ通知認証アプリ 実現可能性調査

調査日: 2026-04-03

## 結論

**実現可能性は高い。** iOS/Android両対応のプッシュ通知認証フローをTypeScriptで構築できる。

---

## 1. プラグイン概要と対応プラットフォーム

- `@capacitor/push-notifications` はCapacitor公式プラグイン
- TypeScript（Webコード）からiOS/AndroidのネイティブPush通知機能へのブリッジを提供
- 対応プラットフォーム: iOS / Android

---

## 2. 認証フローの実現可能性

以下のフローが実現可能:

1. アプリ初回起動時に通知許可を取得 → デバイストークンを取得
2. トークンをユーザー情報と紐付けてサーバーに保存
3. 認証要求時（他デバイスでのログインなど）、サーバーがFCM/APNs経由で通知送信
4. ユーザーが通知をタップ → アプリ起動 → 認証結果をサーバーに送信

このロジックはTypeScriptで共通化可能。

---

## 3. アクション付き通知（承認/拒否ボタン）

- **サポートあり**
- `notificationActionPerformed` イベントリスナーで `actionId`（どのボタンが押されたか）を検知
- バックグラウンド状態からでもアプリの特定ロジックを呼び出せる

---

## 4. FCM / APNs 連携

| 役割 | 担当 |
|------|------|
| デバイストークン取得・通知受信 | `@capacitor/push-notifications` |
| FCM/APNs APIへの通知送信 | サーバーサイド |

- Android: `google-services.json` が必要
- iOS: Xcodeでの Push Notifications ケイパビリティ設定 + 証明書（.p8/.p12）が必要

---

## 5. セキュリティ考慮事項

- クライアント・サーバー間の通信は **HTTPS必須**
- 通知ペイロードに機密情報を含めない（最低限の識別子のみ）
- プッシュトークンだけでは本人性を担保できないため、**生体認証（Face ID / Touch ID）との組み合わせ**が推奨

---

## 6. 主な制限事項

- **バックグラウンド処理の制約**: OSの制約により、通知アクションからの長時間タスクは不可
- **通知UIのカスタマイズ**: 大幅なデザイン変更にはネイティブコードの知識が必要な場合あり
- **OS新機能への追従**: iOS/Androidの新通知機能がプラグインにサポートされるまでタイムラグの可能性あり
